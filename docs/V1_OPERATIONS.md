# 株ゴリラ🦍 v1.0：使う → 記録する → 答え合わせする → 改善する

2026-09-13以降、Phase Bまでの承認済みアプリを日常利用版v1.0として運用する。
UI内部の版番号やTheme Systemの定義・識別子は変更しない。
新機能の追加やUI再設計より、既存機能の安定性、データ保存、重大バグ修正を優先する。

## 保存先の分離

|対象|保存先|記録の契機|
|---|---|---|
|Theme出力、Strength/Velocity/Heat、Turning、Breadth、市場環境、membership、benchmark|Private Shadow repoの既存inputs/manifests等|日次Observation|
|RVOL、1/5/21/63日リターン、順位・順位変化、時点membership|Private Shadow repoのdisplay_observations|日次Phase A sidecar|
|保有／監視判断enum、最大3個の投資根拠タグ、閲覧時の情報|その端末だけのusage ledger|アプリ起動後のデータ取得時、判断変更時、再表示時|
|検証用の予測・モデル・結果|独立したresearch/Shadow台帳|モデルを明示選択した場合のみ|

個人の判断・投資根拠をPublic repoやPrivate Shadow repoへ送信しない。
usage ledgerにも株数・取得単価・資産額・ニュースメモ・自由文は含めない。
既存の判断変更履歴／投資根拠変更履歴と会計台帳は変更しない。

## 端末の利用履歴

`mystockos.usage.v1.<SHA256>` に1件ずつ追記。最後のイベントの参照だけを別キーに保存。
同じ日の同じ状態・同じ閲覧データは重複記録しない。A→B→Aの判断変更は3件残す。
日本時間の日付を記録し、利用しなかった日の値を補完しない。時刻の根拠は端末時計。
Safari/PWAを閉じたまま端末内履歴をバックグラウンド生成する仕組みではない。

記録項目：手動enum、根拠タグ、変更イベントID、対象銘柄に関係するテーマのスコア・
Breadth・Turning・構成・比較基準・表示指標、ソース別as_of/quality/cache状態と内容hash。
日常利用中の状態を予測に見せかけず、shadow_prediction_id=nullを維持する。

設定 → 「利用履歴を書き出す」でJSON保存。通常の「バックアップを書き出す」は既存の
会計・保有等のデータ用であり、利用履歴は別ファイル。端末やSafariのデータ削除・
サイト変更でローカル履歴を失う可能性があるため、定期的に両方を保存する。
利用履歴JSONの自動復元・Privateへの同期はこの版では提供しない。

会計保存領域を圧迫しないよう、利用履歴は概算1MB、origin全体は概算3MBを新規記録の
上限としている。上限・保存失敗では通知し、過去履歴の削除や0埋めはしない。
この上限はブラウザの容量保証ではない。保有・会計の保存処理は利用履歴失敗で巻き戻さない。

## 5 / 20 / 60米国営業日後の答え合わせ

既存のObservation採点：次の取引可能セッションの寄り付きから該当営業日の引けまで、
時点固定Coreのテーマリターン、benchmarkリターン、超過リターン、終値ベースMFE/MAE。
調整方式・価格basis・情報源を保持し、欠損銘柄を0として扱わない。

Private `observation_reviews` に順位変化の答え合わせを追記する。
既存Strengthランキングだけを使い、初期順位−終了順位を改善幅とする。
Thin等の非横断ランキング対象は「対象外」。対象集合が変わった場合や終了日データが
なければunresolved。終了日とは違う日付を代用しない。後から不足が解消した場合も
旧記録を残してsupersedes付きの新バージョンを追記する。

予測のないObservationには方向正解を作らない。direction_correct=null、
direction_status=not_applicable_no_prediction。実際に発行済みのresearch予測だけ、
予測した超過リターンと実現超過リターンの符号を比較する。0予測は対象外。
手動の「保有継続」「押し目待ち」を機械的に方向予測へ変換しない。

## 改善の条件

蓄積履歴の品質を確認した後、時系列OOSでChallengerを比較する。
日次の学習・モデル変更・Champion自動昇格・未検証Forward Scoreの本番売買接続はしない。
研究用コードを実装済みであることと、予測精度が確認できたことを区別する。

## 日常利用の開始

mainのGitHub Pagesを利用する。プレビューとは保存originが違う場合がある。
以前プレビューで入力した個人データは自動で移らないため、必要なら旧画面で既存
バックアップを書き出し、本番の設定から読み込む。移行確認前に旧データを消さない。
株ゴリラ🦍のブランド、5画面ナビ、CSS Scroll Snap、承認済み配色は維持する。
