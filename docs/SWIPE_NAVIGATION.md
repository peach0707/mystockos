# iPhoneの画面スワイプ

ホーム → テーマ → 銘柄 → ニュース → 保有。左へスワイプで次、右へスワイプで前へ移動します。両端では停止し、循環しません。下部ナビのタップも引き続き使えます。

## 判定

- 単一の指、72 CSS px以上、700ms以内、横移動が縦移動の1.8倍より大きいときのみ確定。
- 12px以上動いた時点で縦・斜め方向が認められたら、その指操作中は再判定しない。縦スクロールが12pxを超えた場合も中止。
- 左右28pxの画面端からは開始しない。Safariの戻る・進む操作を優先。
- 入力・ボタン・リンク・フォーム・選択文字・編集フォーカス・横スクロール領域からは開始しない。
- 親5画面のみ有効。テーマ詳細、銘柄詳細、損益カレンダー、設定等では無効。
- 新たな横操作UIには `data-page-swipe="off"` を付けて領域全体を除外できる。
- 全touchリスナーはpassive。preventDefaultやtouch-actionの制限を加えず、スクロール・ピンチズームを維持。

遷移は既存hashルーターで行い、選択ナビ・フォーカス・先頭へのスクロールも既存処理に任せます。移動後の本文だけを24px/170msで軽くスライド。端末の「視差効果を減らす」設定時はアニメーションを省略します。Safariとホーム画面からのstandalone起動で同じコードを使用します。

## 回帰・実機確認

Nodeテストは両モード設定で順序・端・誤判定・除外・キャンセル・アニメーション・解除を検証します。実際のWebKitジェスチャーの確認を代替するものではありません。

Safariとホーム画面追加後の両方で次を確認してください。

1. リンクや入力欄を避けて本文中央を左右へ動かす。5画面の順序・下部ナビ選択が一致する。
2. 小さな動き、縦スクロール、斜め移動ではページが変わらない。
3. 銘柄検索、判断選択、投資根拠の選択、ボタン・リンクは通常どおり操作できる。
4. テーマ・銘柄詳細、保有のカレンダー・フォームではページスワイプしない。
5. 左端からのSafari戻る操作、横スクロール領域、ピンチズームを妨げない。
6. ヘッダー・下部ナビ・ホームバーが干渉せず、「視差効果を減らす」ではスライドしない。

Theme System・会計・判断・投資根拠・API処理・個人データ保存には変更を加えません。
