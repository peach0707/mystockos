# 日別評価・使いやすさ改善版（2026-10-02）

## 記録の仕組み

- 定期実行中の briefing workflow が `data/price_archive.json` に公開終値とドル円を蓄積する。起動の有無や端末の保有内容に依存しない。
- 初期アーカイブは公開済み Git 履歴の実際の `as_of` 終値から復元。株式分割調整済みのヒストリカル配列を過去の株数に掛けない。
- 端末の既知の保有期間と公開アーカイブから、次回起動時に未起動日の評価を補完する。保有株数・取得単価をサーバーへ送らない。
- 日本時間の米国市場引け日で表示し、株価と為替は同じ米国日付で揃える。休日はゼロ損益として記録しない。
- 登録前・所有が不明な期間・必要な価格や為替のない日は推測で埋めない。数量・取得単価変更日は比較の基準日。取引・分割時は保有数量を更新する必要がある。
- 前営業日比は隣接する営業日の同じ保有内容だけを比較する。欠損や保有変更をまたぐ変化を日次損益と呼ばない。現金、配当、手数料、実現損益は対象外。
- 既存 version 6 と同じ保存キーを使用。旧 holdingObservations、手動評価、入出金、配当、取得単価は削除・書換えしない。旧バックアップ互換。

## 画面

ホームの資産サマリー、保有株推移の期間切替、前営業日比と取得単価差の分離、コンパクトな保有カード、検索・並替、カレンダーの金額切替、日別内訳、休場／取得待ち／基準日の区別、任意入力と詳細説明の折りたたみ。

参考にした公式説明：Money Forward ME「資産詳細画面のご紹介」、カビュウ「資産推移を任意期間で表示する」、Delta「Features」。ブランド素材や画面の複製はせず、一覧→推移→内訳の導線を採用。

## 検証

`node --test tests/*.test.js`、`python -m unittest discover -s tests -p 'test_*.py'`、`python tests/check_frozen.py`。Chromium / WebKit の実ブラウザで既存 mobile-smoke・mobile-brokerages に加え `mobile-history.mjs` を実行。すべて架空の保有データで検証し、ユーザーの数量・残高をリポジトリや CI に保存しない。
