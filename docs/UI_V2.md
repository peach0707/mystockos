# 株ゴリラ🦍 UI v2 — 実装と利用手順

この変更はfeature branch上のレビュー用実装。mainへのマージ・本番反映はまだ行っていない。

## 画面

- ホーム：市場判定・VIX独立基準日、自分の方針、rankedテーマTOP3、既存Turning、保有/監視要点、重要ニュース、データ注意事項。
- テーマ：ランキング／初動／失速警戒。ranked5・thin8（family別）・heat_only8・観察8。WeakeningやTurningの既存状態だけで表示。
- 銘柄：保有／監視／すべて。Core/Related/Watchとテーマ指標、自分の投資根拠・判断・買い条件。公開株価があるのは従来の5銘柄だけ。
- ニュース：手動登録、情報源・重要度・関連ID・方向・一次情報確認状態・3行要約・重要理由・元リンク・X下書き。自動投稿なし。
- 保有：総資産、日次損益、年初来資産増減・運用損益、配分、日次評価、カレンダー、配当、運用サマリー。
- 設定：方針、JSON書出し/読込、日次CSV、再読込。データ連携はここに集約。

PDFの青いヘッダー、明るい背景、白いカード、青い選択状態を採用。iPhoneのsafe-areaを考慮した5項目固定ナビ。横幅320pxからのCSS対応、入力文字16px、44px以上の操作領域、フォーカス表示、キーボード・読み上げラベルを備える。実機検証は別途必要。

## 個人データと会計

キー：`mystockos.private.v2`。公開用キャッシュとは別。株数・単価・評価額・投資根拠・配当・入力ニュースはGitHubへ送らない。設定からバックアップを保存できる。localStorageは暗号化保管や端末同期ではないため、同一ブラウザ内の利用とする。保存不能/読み取り破損は黙って初期化・上書きしない。

報告通貨は円。総資産は**現金と受取済み配当を含む**日次評価額として手入力/CSV取込。株価と為替の基準時刻・情報源を記録。取得対象外の保有株価を0や架空値で埋めず、5銘柄の日足を使って不完全な自動資産評価もしない。

- 日次損益＝当日総資産−前日総資産−当日純入金。前暦日の評価がない場合は未算出。休日の評価も明示的に登録する。
- 純入金＝外部入金−外部出金。売買・配当を外部入出金に含めない。
- 日次率＝日次損益/前日総資産。純入金がある日、元本0の日は率を未算出にする。時刻不明の入金からTWRを捏造しない。
- 年初来資産増減＝最終評価−前年12/31評価。
- 年初来運用損益＝資産増減−年初来純入金。全暦日の記録を要求し、欠落日を入出金0とみなさない。銀行入出金台帳連携が追加されたら欠落判定を拡張する。
- 配当は入金日、税引後額×その日の記録FXで計上。円配当はFX=1。総資産に既に入っているため二重加算しない。将来の未収は別status/versionで分離する。
- 株価/FX/実現/その他は利用者が記録した損益内訳。配当と合わせて総損益に照合し、残差を未分類として表示。実現と未実現を二重計上しないよう、株価要因を実現分と排他的に記録する。
- 銘柄別/テーマ別寄与はそれぞれ別分解。同じテーマに多重所属する銘柄は二重割当せず、Home Core等の割当基準を統一して入力する。差額を表示し、不明な寄与を推定しない。
- 訂正は該当日を更新し、日次/年初来表示を再集計。未記録・記録あり・明示休場を区別する。

### 最初の入力

1. 「保有 → 保有銘柄を登録」で株数・取得単価・投資根拠を登録。
2. 「日次評価を記録」で円建て総資産と純入金、価格/FXの評価基準を記録。
3. 年初来を出すには前年12/31から各日の評価・入出金記録を追加。記録なしの期間は未算出。
4. 配当は実入金後に「配当内訳」で入力。
5. 設定でバックアップを保存。CSVテンプレートはヘッダーのみで、架空の資産額は入っていない。

CSV列：`date,assets_jpy,net_flow_jpy,basis,status`。数値は桁区切りなし。値にカンマを含む場合はCSV引用符を使う。`status`は`recorded`または`closed`。JSONは画面から書き出したversion2形式。取込は全体検証・件数表示後に反映する。同日CSVは評価等を更新し、既存寄与/配分明細を保持、配分不一致が生じれば取込を拒否する。

### ニューススキーマ

`id,date,title,source,url,importance(high/normal/low),themes[],tickers[],sentiment(positive/negative/neutral),verified,summary[3],why`。

現時点のverifiedは人が元一次情報を確認した申告。自動検証済みと表現しない。ニュース自動収集は将来このスキーマに対応する別コレクターとし、UIはAPIキーを持たない。配信契約・取得間隔・転載条件・重複排除を決める前に本番収集は追加しない。
